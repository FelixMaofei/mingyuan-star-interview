# 「明星闪耀」已确认格式

使用本页组织本次采访确认稿。栏目与俱乐部以采访者确认为准。

## 固定栏目层级

```markdown
> **明星闪耀｜Super AI Lab人物访谈 NN**

# [人物名]

> [清楚、有事实支撑、能帮助读者进入人物的一句副标题]
```

如果系列编号未确认，省略 `NN`，不要写 `00`、`待定`或自行推断。

## 固定系列序言

Super AI Lab 的「明星闪耀」可复用下面的导语。最后一段换成当前人物，只预告逐字稿中有依据的内容。其他俱乐部使用自己的系列背景。

```markdown
## 序｜关于「明星闪耀」

“明星闪耀”是Super AI Lab一直坚持的口号。

这里所说的明星，是我们的每一位会员——每一个愿意表达、实践、分享，并在这里留下自己光亮的人。

因此，我们发起了「明星闪耀」人物访谈。

第一阶段，我们会先从Super AI Lab的官员开始，聊聊他们为什么来到头马，为什么愿意接下官员角色，在俱乐部里经历过什么，又怎样理解成长、表达、AI和人与人之间的关系。

以后，我们也希望和这里的每一位伙伴坐下来聊一次。

这不是一组官员履历，也不只记录完成了哪些工作。我们更想留下一个个真实的人：他们怎样来到这里，在意什么，改变了什么，还有哪些事情依然没有答案。

也希望通过这些真实的谈话，让每个人被更完整地看见，让更多人通过他们，认识Super AI Lab。

这一期，我们先来认识[人物名]。

[用一小段介绍本篇人物主线，不超过两段，不替受访者宣布成长完成。]
```

## 分节格式

正文最多七个编号部分。每个部分使用：

```markdown
## 一｜[能说明这一节内容的主标题]

> “[当前逐字稿中清楚、有支撑的原话副标题]”
```

主标题应像“把第一次开口的机会留给新人”，能让读者预判本节内容。避免只写“沟通、变化、期待”这种信息量过少的标题。

七个部分是上限，不是必须填满。按当前人物素材合并，依据本次素材划分。

## 问答编辑示例

优先保留受访者自己的完整表达：

```markdown
**采访者：你为什么会这样想？**

**受访者：**[保留有实质内容的完整回答，去除赘词和近距离重复。]
```

当原始对话是“采访者 长篇解释／诊断 → 受访者：对”，通常删除这一组，或保留受访者前面已经说清的原话。不要用“对”证明受访者认领采访者的全部解释。

采访者有价值的观察可以移入结语，并明确是采访者的视角。

## 确认稿开头

```markdown
# 给[人物名]的确认说明

这是一版根据采访录音整理的人物访谈稿，目前尚未发布。

整理时已去除明显的语音转写错误、口语重复和不适合公开的私人内容，尽量保留原始问答和你的表达。请重点确认：

1. 人物、时间、经历和官员角色是否准确；
2. 文中的原话和表达是否符合你的本意；
3. 是否有不希望公开、希望弱化或需要补充的内容。

---
```

## 结语标准

保真约束针对事实和观点归属，不禁止作者提炼意义。正文写受访者实际说过什么；结语可由实际署名的采访者说明“我看见了什么、为什么值得留下、读者可以怎样理解”，把采访中的具体经历与判断连接起来。用户本人写入的感想是作者表达，不能要求每句都在逐字稿中出现。

代拟结语时，依据本次材料和用户已经表达的观察提出判断；个人记忆、既有交情和额外事实不能自行补写。无需固定列几点，也无需每篇都写宏大的结论。见[虚构采访的编者结语示例](example.md)。

结语可以回答：

- 这次谈话让采访者看见了一个怎样的人；
- 哪种真实特质或选择值得记住；
- 想对Super AI Lab会员、嘉宾、现场观众、听众或读者说什么。

结语不能：

- 把未完成的变化写成已经完成的蜕变；
- 把复杂的人压成“沟通力／领导力典范”；
- 暴露确认清单、提示词、审核过程和内部维护规则；
- 为了营销制造不存在的金句或号召。

## 交付边界

默认只生成确认 Markdown。受访者确认前：

- 不删除顶部确认说明；
- 不写入公众号草稿箱；
- 不宣称可发布或已发布；
- 不生成 PDF、HTML、图片或排版稿，除非采访者在当前请求中明确要求。
